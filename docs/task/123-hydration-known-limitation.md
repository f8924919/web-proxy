## 結論

ブラウザモードの React hydration エラー（`#418` 等）は **実害なし（コンソールノイズ）** と切り分けた。低減策は体験を壊すリスクがあり割に合わないため、**既知の制約として docs 化してクローズ**する（方針はユーザー確認済み）。

## 切り分け（実測・2026-06-23）

現 main（#120・#124 修正済み）で `news.yahoo.co.jp` をブラウザモードで取得:

- console: React `#418` ×36 / `#423` ×1 / `#425` ×1、加えて `YAHOO is not defined` / `yadsRenderAd_v2 is not defined`（第三者広告由来・hydration 無関係）。
- 描画: ヘッダー・トップニュース（画像付き）・各ランキング（サムネ付き）・フッターすべて正常表示。**hydration エラーによる見た目の崩れ・コンテンツ欠落なし**。
- 残る見た目の欠落（「あなたにおすすめ」403・動画プレイヤー黒box）は hydration ではなくターゲット側の認可/プレイヤー要件。

### なぜ実害が出ないか

React `#418` は「hydration 失敗 → クライアントで再生成」。ブラウザモードの配信 DOM は既に `page.content()` で完全レンダリング済みで、同じ React アプリが同じ埋め込みデータで再描画するため、視覚的な結果は変わらない。

## 低減策の評価（採らない）

- `__NEXT_DATA__` 等の hydration マーカー除去・框架ブートストラップ抑止で再 hydration を止めればエラーは消せるが、**SPA のクライアント操作性・動的更新を壊すリスク**があり、得られるのはノイズ低減のみ。
- 配信 DOM の静的スナップショット化（框架スクリプトを配信しない）は体験を大きく変える別検討事項。
- → 低減策は実装せず、既知の制約として明記する。
